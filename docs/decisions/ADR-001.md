# ADR-001 — Keep one application and one database

Status: accepted; retained from the Week 1 decision.

The workload is small and the product has one request workflow. A React frontend, a NestJS backend and a single database are enough. Splitting this into microservices would add operational failure points without improving the assignment's user journey.

The final release keeps that decision. NestJS serves React and accesses durable libSQL storage when hosted. Gemini is an external reviewer behind backend validation, not another authority over workflow state. See the [original decision record](../../decisions.md) for the initial options and the later advisory-AI decision.

Consequences: one application is easy to run and inspect; a backend outage affects the whole demo. Health checks, logs, a release gate and a recovery procedure are therefore part of the handoff.
